# 校味技术路线

## 架构

| 层 | 实现 | 作用 |
| --- | --- | --- |
| 产品界面 | HTML、CSS、原生JavaScript | 登录、分类搜索、地图、菜品、点评打卡、个人与商家页面 |
| 业务模型 | CampusModel | 示例数据、菜品与订单状态、偏好、打卡、留言、推荐和迁移 |
| 图片 | SVG菜品插画／浏览器JPEG压缩 | 插画示意、用户实拍优化 |
| 页面与接口 | Vinext／React + /api/state | 承载页面、登录与快照读写 |
| 账号与访问 | Sites平台身份 | 稳定账号键与当前站点访问边界 |
| 数据保存 | Cloudflare D1 + Drizzle | 账号快照、版本与更新时间 |
| GitHub Pages | docs/index.html | 单文件本机体验，不使用云端API |

## 文件组织

- `public/app/app.js`：产品界面、路由、模拟角色、地图层级、详情与表单。
- `public/app/core.js`：菜品、商家、点评、打卡、留言、订单及推荐规则。
- `public/app/art.js`：菜品、咖啡与饮品SVG插画。
- `public/app/boot.js`：云端初始化、本机保留、自动保存与版本冲突。
- `public/app/style.css`：响应式视觉样式。
- `app/api/state/route.ts`：身份与来源检查、快照读写、乐观版本控制。
- `lib/state-validation.ts`：数据集合、对象关系、分类、位置、价格、状态与图片校验。
- `scripts/make-demo.mjs`：生成GitHub Pages和备用单文件版本。

## 数据

保留原账号快照表以兼容已保存记录。快照包含 `shops、dishes、prefs、favorites、reviews、orders、wishes`，新增 `checkins、feedback、profile、schemaVersion`。

旧记录在客户端迁移，补齐地图归属、楼层、档口、分类与新增集合，保留已有点评和预约。此次重构不更改已应用的SQL迁移。

## 推荐

首页以评分、目标、口味、历史收藏／本人高分点评／打卡、近期习惯与等待时间排列菜品，普通浏览保留完整分类内容。

用餐助手按显式用餐人数和每人预算生成方案，解析简单人数、预算、口味、目标、忌口和品类表达。明确“不辣”等口味时进行相应筛选；收藏与历史记录影响排序。转盘只在匹配预算、忌口、营业和在售状态的主食候选中随机选择。

推荐为规则演示，不使用大模型API、营养测量或设备人流识别。可在后续保留这些结构化约束，再接入真实AI模型生成解释或澄清。

## 同步与角色

模拟角色由sessionStorage记录，退出后回到身份选择页。业务记录先保存在本机，再以版本号提交云端。服务端采用条件写入；冲突返回409，失败保留本机未同步标记并提供重试、导出与确认读取云端。

账号隔离由平台身份与服务端查询条件实现；角色是同一账号体验沙盒的产品模拟，并非真实商家RBAC。

## 地图边界

地图由可点击SVG与关联数据实现，包含校园点位、食堂楼层、档口和菜品四级对象。食堂名称有校方资料依据，几何布局和门店服务数据均为模拟；没有定位、实时导航或传感器接入。

## 构建与验证

`pnpm test` 验证身份入口、15个视图、地图层级、点评打卡、反馈、分人配餐、分类、角色导航、预约与历史数据迁移，以及云同步行为。

`pnpm typecheck`、`pnpm build` 完成类型与Worker构建检查。`pnpm demo:build` 生成自包含HTML。

当前执行环境没有受支持的浏览器控制，真实手机视觉与网络可达性仍需人工验收。GitHub Pages首次开通需仓库管理员在Settings → Pages选main /docs；现有连接工具不能修改这个设置。
